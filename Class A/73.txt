
I am a student with a strong interest in computer science and software development, and I have gradually become interested in cybersecurity. As I started building web applications and learning about networks, databases, and cloud systems, I realised that creating software is only one part of the process. It is also important to make sure that the software, data, and users are protected. This made me interested in understanding how cybersecurity works.

My interest in cybersecurity developed mainly through software development. When I started building applications, I focused on making the features work correctly. I learned how to create user interfaces, develop backend services, connect databases, and build APIs. As I worked on more projects, I started thinking about what could happen if someone used the application in an unexpected or harmful way.

This led me to learn about basic security concepts.

I started exploring topics such as authentication, authorisation, passwords, input validation, secure APIs, encryption, and access control. These concepts helped me understand that security needs to be considered while designing an application rather than added only after development is complete.

One of the first areas I became interested in was authentication.

Many applications require users to create accounts and log in. At first, I mainly thought about the login interface and whether the correct user could access the application. Later, I understood that authentication involves several security considerations.

Passwords should not be stored in plain text.

User sessions need to be managed securely.

Access to different resources needs to be controlled.

Input from users needs to be validated.

These concepts made me realise that even a simple login system involves important security decisions.

I also became interested in authorisation.

Authentication answers the question of who the user is, while authorisation determines what that user is allowed to do.

For example, an application may have different types of users with different permissions. A normal user should not automatically have access to administrative functions.

Understanding this distinction helped me think more carefully about access control in the applications I build.

Another area I explored was input validation.

Applications receive information from users, and that information cannot always be assumed to be correct.

Users may accidentally enter invalid information.

An application may also receive deliberately manipulated input.

Therefore, input should be validated before it is processed.

This is important for both application reliability and security.

Learning about these concepts made me more careful when developing APIs and backend services.

I also became interested in common web application vulnerabilities.

I learned about concepts such as SQL injection, cross-site scripting, insecure authentication, and improper access control.

Understanding these vulnerabilities helped me realise how small mistakes in application development can create larger security problems.

For example, if user input is directly included in a database query without proper protection, an attacker may be able to manipulate the query.

Similarly, if an application does not properly validate permissions, a user may be able to access information that should belong to someone else.

These examples showed me why secure development practices are important.

My experience with databases also influenced my interest in cybersecurity.

Applications often store information such as user accounts, transactions, documents, and other data.

If the database is not protected properly, this information can be exposed.

I learned that database security involves access control, secure credentials, validation, backups, and other practices.

This made me more interested in how data is protected throughout an application.

Cloud computing also increased my interest in cybersecurity.

As I learned how applications are deployed on cloud platforms, I realised that security is not limited to application code.

Cloud infrastructure also needs to be configured correctly.

Permissions need to be controlled.

Storage needs to be protected.

Network access needs to be managed.

Sensitive credentials should not be exposed.

This showed me that modern security requires understanding the entire system.

My interest in artificial intelligence has also made me think about cybersecurity from another perspective.

AI systems themselves need to be protected.

They may process sensitive data.

They may depend on external APIs.

They may be connected to databases or other services.

If an AI application is not designed securely, attackers may be able to manipulate inputs or access information they should not have.

I want to learn more about the security challenges associated with AI systems.

At the same time, AI can also be used to support cybersecurity.

Machine learning models can analyse large amounts of information and identify unusual patterns.

This could potentially help detect suspicious activity or identify anomalies.

I find this combination of AI and cybersecurity interesting because it connects two areas of computer science that I enjoy.

However, I also understand that AI-based security systems have limitations.

An anomaly does not always mean that an attack has occurred.

A model can produce false positives or false negatives.

Therefore, such systems need proper evaluation and human oversight.

I want to understand these limitations as I learn more.

Another area of cybersecurity that interests me is network security.

Modern applications communicate over networks, and information needs to be transmitted securely.

I want to understand how protocols, firewalls, encryption, and other security mechanisms help protect communication.

I have learned some basic networking concepts, but I want to study them in greater depth.

Understanding networks will help me understand how attacks and defences work at different levels.

Encryption is another topic I find interesting.

Encryption allows information to be transformed so that it cannot be easily understood by unauthorised users.

It is used in many areas of modern technology, including secure communication and data storage.

I want to understand the basic mathematical ideas behind cryptography rather than only using encryption libraries.

This is one reason I want to strengthen my mathematics and computer science fundamentals.

I also want to understand public-key and symmetric-key encryption, hashing, digital signatures, and other cryptographic concepts.

These topics are important for secure software systems.

My interest in cybersecurity has also made me more aware of the importance of software updates.

Applications depend on libraries and frameworks that may contain vulnerabilities.

If these dependencies are not updated or managed properly, an application may become vulnerable.

This has encouraged me to think about dependency management and secure development practices.

I want to learn more about software supply-chain security as I gain experience.

Another important area is security testing.

Developers should not only test whether an application works.

They should also consider how it behaves when it receives unexpected input or when someone tries to access restricted functionality.

Security testing can help identify weaknesses before they are exploited.

I want to gain practical experience with security testing in a controlled and ethical environment.

I believe ethical behaviour is particularly important in cybersecurity.

Security knowledge can be used to protect systems, but it can also be misused.

I want to study cybersecurity from a defensive and responsible perspective.

My goal is to understand how systems can be made more secure and how vulnerabilities can be identified so that they can be fixed.

I also want to learn about responsible disclosure and the importance of reporting security issues appropriately.

Another aspect of cybersecurity that interests me is human behaviour.

Many security problems are not caused only by technical weaknesses.

People may use weak passwords.

They may click on suspicious links.

They may share sensitive information without checking the source.

They may accidentally expose credentials.

This means cybersecurity also involves education and awareness.

Technical systems can be designed securely, but users still need to understand basic security practices.

I find this human side of cybersecurity interesting because it shows that security is not only a technical problem.

It involves people, processes, and technology.

My experience with software projects has helped me understand the importance of thinking about security from the beginning.

When designing an application, I want to consider what information it collects, who should have access to it, how the information is stored, and how communication is protected.

This is different from adding security after the application is complete.

I want to develop secure-by-design thinking.

I also want to learn more about threat modelling.

My participation in technical projects has also taught me that security needs to be balanced with usability.
