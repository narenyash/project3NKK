The application also needed to be deployed.

The backend needed to run on a server.

The database needed to be accessible securely.

The frontend needed to communicate with the backend.

The system needed to remain available even when I was not running it from my own computer.

This introduced me to cloud computing.

I started learning about different types of cloud services and how applications can be deployed using cloud infrastructure.

I found it interesting that developers do not always need to purchase and maintain physical servers themselves.

Instead, they can use computing resources provided by cloud platforms.

This makes it easier to develop and deploy applications.

One of the first concepts I explored was cloud-based hosting.

A web application can have its frontend hosted separately from its backend.

The backend can run on a cloud server and communicate with a database.

Users can then access the application through the internet.

This helped me understand how the different parts of a software system communicate in a production environment.

It also made me more interested in system architecture.

When developing an application locally, everything can appear simple.

The frontend communicates with the backend.

The backend communicates with the database.

However, a production application needs to consider many additional factors.

It needs authentication.

It needs security.

It needs monitoring.

It needs error handling.

It needs scalability.

It may need backups.

It may also need to handle many users at the same time.

Cloud computing provides tools that can help manage these requirements.

I find this practical side of software engineering interesting.

Another concept that interests me is scalability.

Caching may be required.

A network connection can fail.
