# Essay A092 — My Interest in Human-Computer Interaction

I am a student with a strong interest in computer science, artificial intelligence, and software development. While learning about technology and building different applications, I have become increasingly interested in how people interact with computers. This area is known as human-computer interaction, or HCI. I find it interesting because developing a technically strong application is not enough. The application should also be easy to understand, comfortable to use, and designed according to the needs of its users.

My interest in human-computer interaction developed through my experience with software development. When I first started building applications, I mainly focused on making the features work. I would think about the programming language, backend, database, API, and other technical components.

If the application performed the required function, I considered the project successful.

As I worked on more projects, I started noticing that users interacted with applications differently from how I expected.

A feature that seemed obvious to me was sometimes confusing to another person.

A button that I thought was easy to find could be missed.

A page with many features could become difficult to understand.

A technically correct application could still provide a poor user experience.

This made me realise that software development is not only about functionality.

It is also about people.

This is what attracted me to HCI.

One of the first things I became interested in was usability.

Usability refers to how easily people can use a system to achieve their goals.

An application may contain many advanced features, but if users cannot understand how to use them, those features may not provide much value.

I started paying more attention to the number of steps required to complete an action.

For example, if a user wants to perform a simple task, the application should not require unnecessary navigation.

Reducing unnecessary steps can make an application easier to use.

This seems like a simple idea, but it can have a significant effect on the overall experience.

Another concept I find important is simplicity.

When developing software, it is tempting to add many features.

However, adding more features does not automatically make an application better.

Too many options can make an interface difficult to understand.

Users may not know which action they should take.

I have learned that a good interface should provide the necessary information without overwhelming the user.

This has influenced how I design my own projects.

I now try to think about what the user actually needs before deciding what features to include.

Another area I find interesting is user research.

Developers cannot always understand user requirements simply by making assumptions.

Talking to users can reveal problems that developers may not notice.

Users can explain what they currently do, what they find difficult, and what they would like to improve.

This information can help guide the design process.

I find this useful because it changes the development process from simply building what I think is useful to understanding what other people actually need.

One experience that taught me this was working on an application for organising information.

I initially designed the interface based on what seemed logical to me.

After showing it to other students, I received different feedback.

Some users wanted fewer options on the main screen.

Others wanted important information to be visible immediately.

Some preferred a different navigation structure.

This showed me that different users can have different expectations.

Instead of treating the feedback as criticism of the project, I used it to improve the design.

This experience made me more comfortable with testing and revising my ideas.

Another concept I find important is accessibility.

Technology should not only be designed for users who have perfect vision, hearing, mobility, or technical knowledge.

People have different abilities and different ways of interacting with devices.

Applications should consider these differences.

For example, interfaces should have readable text, appropriate contrast, keyboard accessibility, meaningful labels, and other features that can support different users.

Accessibility has become an important part of my understanding of good software design.

My interest in accessibility is also connected to my work with artificial intelligence.

AI can potentially provide new ways for people to interact with technology.

Voice interfaces can allow users to give spoken commands.

Computer vision can help interpret gestures.

Natural language processing can allow users to communicate through ordinary language.

These technologies can potentially make applications more accessible.

However, they also need to work reliably for different users.

This is an area I would like to explore further.

Another topic I find interesting is user interface design.

A user interface is the part of the system that users interact with directly.

This can include buttons, menus, forms, navigation systems, dashboards, and other components.

Good interface design should make the purpose of each element clear.

For example, a button should communicate what will happen when the user selects it.

Forms should provide useful instructions.

Error messages should explain what went wrong and how the user can correct it.

These details can have a significant effect on the user experience.

I have become more careful about these details while building applications.

Another important concept is consistency.

If different parts of an application use different layouts, icons, colours, or interactions for similar functions, users may become confused.

Consistent design makes an application easier to learn.

For example, if a certain type of button performs an action in one part of the application, a similar button should generally behave in a similar way elsewhere.

This reduces the amount of learning required from the user.

I find this principle useful when designing larger applications.

Another area I am interested in is navigation.

Applications can contain many pages and features.

Users need to understand where they are and how to reach another part of the application.

A confusing navigation structure can make even a well-designed feature difficult to use.

I want to understand how information architecture can be used to organise applications effectively.

This is especially important for large websites and software platforms.

Another concept I find interesting is feedback.

When a user performs an action, the system should usually provide some indication of what happened.

For example, after submitting a form, the application should show whether the submission was successful.

If an operation takes time, the interface may need to show a loading state.

If an error occurs, the user should be informed.

Without feedback, users may not know whether the system has received their action.

This can lead to repeated actions or confusion.

I have learned to consider these situations while developing applications.

Another important area is error handling.

Users will make mistakes.

They may enter information in the wrong format.

They may forget a required field.

They may select an incorrect option.

A good interface should help users recover from these mistakes.

An error message should not simply say that something went wrong.

It should ideally explain what needs to be corrected.

This is a small part of software development, but it can make a large difference to usability.

Another topic I find interesting is forms.

Many applications require users to enter information.

Forms can become frustrating if they contain too many fields or provide unclear instructions.

Developers should collect only the information that is necessary.

Fields should be organised logically.

Input should be validated appropriately.

Users should be able to understand what is expected.

I find form design interesting because it combines technical validation with user experience.

Another area I want to explore is mobile user experience.

Mobile devices have smaller screens than computers.

Users may interact with them using touch instead of a mouse and keyboard.

This changes how interfaces should be designed.

Buttons need to be large enough to select comfortably.

Important information should be visible without unnecessary scrolling.

Navigation should be simple.

Performance is also important because mobile users may have slower connections or less powerful devices.

My experience with mobile application development has made me interested in these challenges.

Another important concept is responsive design.

Websites may be accessed from phones, tablets, laptops, and large monitors.

An interface should adapt appropriately to different screen sizes.

A layout that looks good on a large screen may not work well on a small phone.

I have learned to consider different devices while developing web applications.

This has helped me understand that design cannot be separated completely from the environment in which the application is used.

Another area I find interesting is performance and user experience.

Users may not know whether a slow application is caused by the frontend, backend, database, or network.

They simply experience the application as slow.

Therefore, technical performance can directly affect user experience.

Optimising APIs, databases, images, and frontend code can improve how an application feels to users.

This connection between software engineering and HCI interests me.

Another important factor is loading time.

If a page takes too long to load, users may leave before seeing the content.

Applications should therefore provide useful feedback while information is being loaded.

Skeleton screens, progress indicators, and other techniques can help communicate that the system is working.

I find these small design decisions interesting because they influence how users perceive performance.

Another area I want to understand is trust.

Users need to feel comfortable when interacting with an application.

Clear information, predictable behaviour, appropriate security features, and transparent communication can increase trust.

For example, an application requesting sensitive information should explain why the information is required.

Users should not be surprised by unexpected actions.

This is especially important for applications involving finance, healthcare, or personal information.

My interest in cybersecurity has also influenced my understanding of trust.

Security features should protect users without making the application unnecessarily difficult to use.

This creates an important balance.

A system can be highly secure but difficult to use.

If security processes are too complicated, users may look for unsafe shortcuts.

Therefore, security and usability should be considered together.

Another area I find interesting is authentication design.

Login systems are necessary for many applications, but they should also be easy to understand.

Users need clear information about passwords, verification, and account recovery.

Multi-factor authentication can improve security, but the process should still be understandable.

I want to explore how secure systems can also provide good user experiences.

Another topic I want to study is personalisation.

Different users may have different needs and preferences.

Applications can potentially adapt interfaces based on user behaviour or settings.

For example, a dashboard could show the information most relevant to a particular user.

AI can potentially help with this by identifying patterns in how people use an application.

However, personalisation should not become confusing or make the system unpredictable.

Users should still have control over important settings.

I find this balance interesting.

Another area I want to explore is conversational interfaces.

Natural language processing allows people to interact with computers using ordinary language.

Instead of navigating through many menus, a user could ask a question or describe what they want to do.

This can make some systems easier to use.

However, conversational interfaces can also create uncertainty.

Users may not know what the system can or cannot do.

The system therefore needs to communicate its capabilities clearly.

I want to understand how conversational interfaces can be designed effectively.

Another area I find interesting is voice interaction.

Voice interfaces can be useful when users cannot easily interact with a screen.

They can also be convenient when someone is performing another task.

However, speech recognition can be affected by accents, background noise, pronunciation, and language.

This makes voice interaction a challenging HCI problem.

India's linguistic diversity makes this particularly interesting.

A voice system designed only around a narrow set of speakers may not work equally well for everyone.

I want to explore how AI can support more inclusive voice interfaces.

Another important area is multimodal interaction.

People do not always communicate through one method.

They may use speech, text, gestures, images, touch, and other forms of interaction.

Modern AI systems can potentially combine several of these inputs.

For example, a user could show an image and ask a spoken question about it.

The system would need to process both visual and language information.

I find this direction of HCI particularly interesting.

Another topic I want to understand is gesture-based interaction.

Cameras and sensors can detect movements and gestures.

These can be used to control applications or communicate information.

Gesture interaction may be useful in situations where touch or speech is inconvenient.

However, gestures need to be designed carefully.

Users should understand which movements are recognised and what they mean.

I want to explore how computer vision can support gesture-based interfaces.

Another area I find interesting is virtual and augmented reality.

These technologies create different ways of interacting with digital information.

Users may move through virtual environments or see digital information overlaid on the physical world.

This creates new HCI challenges.

Traditional interface principles may not always apply directly.

Developers need to think about spatial interaction, movement, visual information, and user comfort.

I would like to learn more about these technologies.

Another important concept is user testing.

A developer may believe that an interface is easy to use, but that assumption should be tested.

Users can be asked to complete specific tasks while their difficulties are observed.

The results can identify problems in navigation, wording, layout, or functionality.

I find user testing useful because it provides evidence instead of relying only on personal opinion.

Another method is usability testing with prototypes.

A complete application does not always need to be built before testing an idea.

A simple prototype can be created to test the layout and interaction.

If users struggle with the prototype, the design can be changed before significant development time is spent.

This can make the development process more efficient.

I want to learn more about prototyping methods.

Another area I find interesting is design iteration.

A first design is rarely perfect.

Developers can collect feedback, identify problems, make changes, and test again.

This process can continue until the system becomes easier to use.

I have experienced this process in my own projects.

Instead of seeing changes as extra work, I have started seeing them as part of development.

Another concept I want to understand is cognitive load.

Users have limited attention and working memory.

An interface that presents too much information at once can make it difficult to understand.

Organising information into meaningful groups can reduce this problem.

This is particularly important for dashboards and complex applications.

I want to learn how HCI principles can help design interfaces that are easier to understand.

Another area I find interesting is dashboard design.

Dashboards often contain large amounts of information.

The challenge is deciding which information should receive attention.

Important information should be easy to find.

Less important information should not distract from the main task.

Visual hierarchy can help guide the user's attention.

I have become more interested in dashboard design while working with data-driven applications.

Another important area is data visualisation.

Users may need to understand trends, comparisons, or changes over time.

Charts can communicate this information more effectively than large tables.

However, visualisations need to be accurate.

Poor design can lead users to misunderstand the data.

I want to improve my understanding of how data visualisation and HCI work together.

Another topic I find important is accessibility for users with visual impairments.

Applications can support screen readers through appropriate semantic structures and labels.

Images can include meaningful alternative descriptions where necessary.

Text should have sufficient contrast and appropriate sizing.

Interactive elements should also be accessible through keyboards or other input methods.

These are technical decisions that can make a major difference.

I want to learn more about accessibility standards and inclusive design.

Another area is accessibility for users with hearing impairments.

Video and audio content can include captions or transcripts.

Important information should not be communicated only through sound.

Visual indicators can provide additional information.

I find this important because inclusive design should consider different types of users.

Another area I want to explore is accessibility for users with motor difficulties.

Some users may find precise mouse movements or small touch targets difficult.

Keyboard navigation, voice control, larger interaction areas, and other features can help.

This connects HCI with my interest in assistive technology.

I believe technology should be designed so that more people can use it independently.

Another important topic is localisation.

An application designed for one country or culture may not automatically work well in another.

Language, date formats, currency, symbols, colours, and user expectations can differ.

India itself contains many languages and cultural contexts.

Designing applications for diverse users therefore requires flexibility.

I want to understand how software can be localised effectively.

Another area I find interesting is multilingual interface design.

Users may prefer to interact with applications in their local language.

Translating text alone may not be enough.

The entire interface should remain understandable and consistent.

AI and NLP can potentially help support multilingual applications.

I would like to explore this area further.

Another important part of HCI is understanding user behaviour.

Analytics can provide information about which parts of an application users interact with.

For example, developers may identify pages where users frequently leave or features that are rarely used.

This information can help guide improvements.

However, user analytics should respect privacy.

Data should be collected responsibly and used for a clear purpose.

This connects HCI with my interest in data science and privacy.

Another area I want to explore is A/B testing.

Developers can sometimes compare two versions of an interface to determine which performs better for a specific goal.

For example, two different layouts may be tested.

The results can provide evidence about user behaviour.

However, the chosen metric needs to represent the actual goal.

A design that increases clicks is not automatically better if it makes the overall experience worse.

I find this balance between quantitative data and qualitative feedback interesting.

Another important concept is user-centred design.

The development process should consider users from the beginning rather than only testing the finished product.

Requirements, design decisions, prototypes, and evaluations can all involve user feedback.

This approach reduces the risk of building something technically correct but practically unsuitable.

I want to apply this approach to future projects.

My experience with AI has also shown me that human-centred design is important for intelligent systems.

AI systems can sometimes produce unexpected results.

Users need to understand what the system is doing.

They may also need ways to correct or reject AI suggestions.

This is particularly important when AI is involved in decision-making.

I want to learn how HCI principles can make AI systems more understandable and controllable.

Another area I find interesting is explainable AI.

If an AI system makes a recommendation, users may want to know why.

For example, a recommendation system may suggest a particular option.

The user may want to understand what information influenced that suggestion.

Providing understandable explanations can improve trust.

However, explanations should be accurate and useful rather than simply adding technical information.

I want to explore how explanations can be designed for ordinary users.

Another topic I want to study is human-AI collaboration.

I do not think AI should always replace human decision-making.

In many situations, AI can provide suggestions while people make the final decision.

This creates a collaborative system.

The interface needs to communicate the AI's confidence and limitations.

Users should be able to review the recommendation and make changes.

I find this approach particularly interesting because it combines AI with HCI.

Another area I want to explore is AI assistants.

AI assistants can help users search for information, organise tasks, write content, analyse data, or interact with software.

The challenge is designing the interaction so that users know what the assistant can do.

The system should also handle mistakes appropriately.

If an assistant takes an action on behalf of a user, confirmation may be needed for important operations.

This creates interesting questions about control, trust, and automation.

I want to study these questions further.

Another important area is emotional design.

People do not interact with software in a completely neutral way.

They may feel frustration when an application fails or satisfaction when a task is completed easily.

Visual design, feedback, language, and interaction can influence these experiences.

I want to understand how design can make technology feel more comfortable without becoming unnecessarily decorative.

Another concept I find useful is progressive disclosure.

An application does not always need to show every available option immediately.

Basic options can be presented first, while advanced options can be made available when required.

This can reduce complexity.

I find this particularly useful for applications with many features.

Another area I want to explore is onboarding.

When users first open an application, they may not know how it works.

A good onboarding experience can introduce the important features without overwhelming the user.

However, long tutorials can also be frustrating.

I want to understand how onboarding can be made useful and efficient.

Another important part of HCI is consistency across platforms.

A user may interact with the same service through a website, mobile application, and other devices.

The interface may look different on each platform, but important concepts should remain consistent.

This allows users to transfer their knowledge from one platform to another.

My experience developing both web and mobile applications has made me more interested in this problem.

Another area I find interesting is the relationship between frontend development and HCI.

Frontend technologies provide the tools for implementing interfaces.

However, knowing how to write frontend code does not automatically mean knowing how to design a good interface.

Developers need to understand layout, accessibility, interaction, performance, and user needs.

I want to improve both my technical and design skills.

My long-term goal is to work in artificial intelligence and software engineering, and I believe HCI will be useful in these areas.

AI systems will increasingly interact directly with users.

Therefore, the quality of the interaction will influence whether people find the technology useful.

A powerful model is not enough if users cannot understand or control the system.

I want to develop technology that is both technically capable and easy to use.

Higher education will give me opportunities to study HCI, software engineering, artificial intelligence, psychology, design, and user research.

I would like to work on projects where I can combine these subjects.

I also want to participate in research related to accessibility, AI interfaces, and human-AI interaction.

Another goal is to gain industry experience.

Working with professional product teams would help me understand how user research and design decisions are handled in real projects.

I want to learn how engineers, designers, researchers, and product teams collaborate.

This would help me develop a broader understanding of software development.

I also want to continue participating in hackathons.

Hackathons often require teams to develop a working prototype quickly.

This makes it tempting to focus only on functionality.

I want to pay attention to the user experience as well.

A prototype should communicate its purpose clearly.

Users should be able to understand how to interact with it.

This is something I want to improve through future projects.

Another goal is to build more accessibility-focused applications.

I am interested in technologies that can provide alternative ways of interacting with computers.

Voice input, computer vision, gesture recognition, and natural language processing can all contribute.

I want to explore how these technologies can work together to create more inclusive systems.

I also want to learn how to evaluate whether such systems actually help users.

Technology should be tested with the people it is intended to support.

This is an important principle I want to follow.

My interest in HCI has changed how I define a successful software project.

Earlier, I mainly asked whether the program worked.

Now I also ask whether users can understand it.

Can they complete tasks easily?

Can people with different abilities use it?

Does the application communicate errors clearly?

Does it protect user information?

Does it behave predictably?

These questions have made me a more careful developer.

I have also learned that good design does not always mean adding more features.

Sometimes the best improvement is removing something unnecessary.

A simpler process can be more useful than a more complicated one.

This is something I want to remember as I continue building applications.

Another lesson is that users are an important source of information.

Developers can make assumptions, but users can reveal problems that developers may never notice themselves.

I want to become more comfortable receiving feedback and changing my designs based on evidence.

This is important for both software development and research.

I know that HCI is an interdisciplinary field.

It combines computer science with design, psychology, communication, and other areas.

This is one of the reasons I find it interesting.

It allows me to use my technical background while also learning about human behaviour.

I want to explore this combination during my higher education.

My long-term goal is to develop technology that people can use naturally and confidently.

I want to work on AI systems, software applications, and intelligent interfaces that solve real problems.

I also want to make sure that these systems are accessible to different types of users.

Technology should not become more difficult simply because it is more advanced.

Instead, better technology should ideally make important tasks easier.

For me, human-computer interaction is interesting because it focuses on the connection between technology and people.

Computers can be extremely powerful, but their usefulness depends on how effectively people can interact with them.

A technically advanced system can still fail if users cannot understand or trust it.

I want to learn how to avoid this problem.

Higher education will help me build a stronger foundation in both technical and human-centred aspects of computing.

I want to continue developing applications, studying AI, learning about accessibility, conducting user research, and improving my understanding of interface design.

I also want to remain open to new forms of interaction as technology develops.

Ultimately, I want to become a technology professional who can build systems that are intelligent, reliable, accessible, and easy to use.

My interest in HCI has shown me that successful technology is not only about what a computer can do.

It is also about how people experience what the computer does.

That is why I am interested in human-computer interaction and why I want to continue exploring this field alongside computer science and artificial intelligence throughout my education and future career.
