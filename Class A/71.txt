
I am a student with an interest in computer science, software development, and artificial intelligence. My interest in cloud computing developed while working on full-stack projects. Initially, I focused mainly on writing the frontend and backend code. I could run the application on my own computer, but I wanted to understand how the same application could be made available to other users through the internet.

This introduced me to deployment.

I learned that developing an application is only one part of the process. The application also needs to be hosted, connected to a database, configured correctly, and monitored after deployment.

This made me curious about cloud computing.

I started learning about basic cloud concepts such as servers, storage, databases, networking, virtual machines, containers, and deployment platforms. These concepts helped me understand how applications can run on infrastructure that is accessed remotely rather than only on a personal computer.

One of the things I find interesting about cloud computing is that it allows developers to access computing resources without having to manage all the physical hardware themselves.

A developer can deploy an application to a cloud platform and make it accessible to users in different locations.

This is useful for modern applications because users may access the same system from different devices and locations.

As I explored cloud computing, I also learned about the difference between developing an application locally and deploying it for real users.

A local development environment may have settings that are not appropriate for production.

For example, applications may use environment variables for sensitive configuration, production databases may have different access requirements, and servers need to be configured to handle real traffic.

This helped me understand the importance of deployment practices.

I have worked with web applications using technologies such as React, Node.js, Express, and MongoDB. Deploying these applications gave me practical exposure to hosting frontend and backend services separately and connecting them to a database.

This experience helped me understand how different components of a software system communicate over the internet.

The frontend can be hosted on one platform.

The backend can run on another server.

The database can be hosted separately.

The application needs to connect these components securely.

Understanding this architecture made me more interested in system design.

I also learned about domains and DNS while working with deployed applications.

A user normally does not need to know the actual server address of an application. A domain can provide a simple way for users to access the system.

Understanding how domains, DNS, servers, and applications connect helped me understand some of the infrastructure behind websites and web applications.

Another important concept I explored was scalability.

A small application may work well when it has only a few users.

However, if the number of users increases, the application may need more computing resources.

Cloud platforms can provide ways to increase resources as required.

This made me interested in how large applications handle traffic.

I want to learn more about load balancing, caching, distributed systems, and other techniques used to improve application performance.

I understand that scalability is not simply about adding more servers.

The application architecture also needs to support growth.

For example, the database may become a bottleneck.

The backend may need to handle more requests.

The system may need to distribute workloads.

These are interesting engineering problems.

I want to study them in greater depth.
