
I am a student with a strong interest in computer science, artificial intelligence, and software development. Along with learning programming and building applications, I have become interested in cloud computing. I find cloud computing interesting because it has changed the way software applications are developed, deployed, stored, and accessed. It allows individuals and organisations to use computing resources without having to manage all the physical infrastructure themselves.

My interest in cloud computing developed through my experience with software development. When I first started building applications, I mainly focused on writing code and running it on my own computer. I understood the application as something that existed within the development environment.

As I worked on larger projects, I realised that building an application is only one part of software development.

The application also needs to be deployed.

Users need to access it.

Data needs to be stored.

Servers need to handle requests.

The system needs to remain available.

Errors need to be monitored.

As the number of users increases, the application may need additional computing resources.

These requirements introduced me to cloud computing.

One of the first concepts I learned was the idea of servers.

A server is a computer system that provides resources or services to other computers.

Web applications often run on servers that receive requests from users and return responses.

Databases can also run on servers.

When I understood this architecture, I became interested in how cloud platforms provide these resources.

Instead of purchasing and maintaining physical servers, organisations can use computing infrastructure provided through cloud platforms.

This makes it easier to start and scale applications.

Another concept I find interesting is virtualisation.

Virtualisation allows physical computing resources to be divided into virtual environments.

Different virtual machines can run on the same physical hardware.

This allows computing resources to be used more efficiently.

Learning about virtualisation helped me understand how cloud providers can offer computing resources to many different customers.

Another area I became interested in is infrastructure as a service.

Instead of purchasing physical hardware, an organisation can rent computing, storage, and networking resources.

The organisation can then configure these resources according to its requirements.

This provides flexibility.

A small project may require only limited resources.

A larger application may require much more.

The infrastructure can be adjusted according to demand.

I find this flexibility one of the most useful aspects of cloud computing.

Another concept I want to understand is scalability.

An application may have a small number of users when it is first launched.

If the application becomes popular, the number of requests can increase significantly.

A system that worked well for a small number of users may not perform well under much higher demand.

Cloud infrastructure can provide additional resources when required.

This makes scalability an important part of cloud architecture.

Another related concept is elasticity.

Scalability refers to the ability to handle increased demand.

Elasticity focuses on adjusting resources according to changing demand.

For example, a system may require more resources during peak hours and fewer resources during periods of low activity.

Using only the required resources can improve efficiency.

I find this concept interesting because it connects infrastructure with real-world usage patterns.

Another area I want to explore is load balancing.

When many users access an application, requests may need to be distributed across multiple servers.

A load balancer can help distribute these requests.

This prevents one server from becoming overloaded while others remain underused.

Load balancing can also improve availability.

I find this useful because it shows how cloud systems can handle large numbers of users.

Another important concept is availability.

Users expect online applications to remain accessible.

A server failure should ideally not make an entire service unavailable.

Cloud architectures can use multiple instances, locations, or other mechanisms to reduce the impact of individual failures.

This introduces me to the idea of designing systems for failure rather than assuming that every component will always work.

I find this an important lesson for software engineering.

Another area I find interesting is fault tolerance.

Failures can occur in hardware, networks, software, or other components.

A reliable system needs to handle these failures appropriately.

For example, if one application server stops working, traffic can potentially be redirected to another server.

If data is stored redundantly, a hardware failure may not result in permanent data loss.

I want to learn more about how cloud systems achieve fault tolerance.

Another concept I want to understand is redundancy.

Important systems often maintain multiple copies or instances of critical components.

This may increase resource usage, but it can improve reliability.

The appropriate level of redundancy depends on the requirements of the application.

I find this an interesting example of the trade-offs involved in system design.

Another area I became interested in is cloud storage.

Applications often need to store images, videos, documents, backups, and other files.

Cloud storage can provide scalable storage without requiring organisations to maintain physical storage systems themselves.

Different types of cloud storage can be used for different requirements.

I want to understand how storage systems are designed and how data can be stored efficiently.

Another important concept is object storage.

Object storage is useful for storing large amounts of files and other unstructured data.

It can be used for images, videos, backups, datasets, and many other types of information.

I have become interested in object storage because many of my software projects involve handling files and datasets.

Understanding how these files can be stored securely and efficiently is important for production applications.

Another area I want to explore is cloud databases.

Applications need databases to store information about users, products, transactions, and other data.

Cloud platforms can provide managed database services.

These services can handle some of the infrastructure and maintenance requirements.

This allows developers to focus more on the application itself.

I find managed services useful because they demonstrate how cloud computing can simplify infrastructure management.

Another concept I find interesting is database scalability.

As the amount of data and number of users increase, a database may need additional resources.

Different scaling approaches can be used.

A database can sometimes be scaled vertically by increasing the resources available to one machine.

It can also be scaled horizontally by distributing data or workloads across multiple systems.

I want to understand the advantages and limitations of these approaches.

Another area I want to learn is caching.

Applications often need to retrieve the same information repeatedly.

Instead of calculating or retrieving the information from the main database every time, frequently used information can sometimes be stored in a faster cache.

Caching can reduce database load and improve response times.

I find this useful because performance is an important part of cloud applications.

Another important concept is content delivery networks.

Users may access applications from different geographic locations.

A content delivery network can distribute certain content through locations closer to users.

This can reduce latency and improve performance.

I find this interesting because it shows how cloud infrastructure can improve the experience of users in different parts of the world.

Another area I want to explore is serverless computing.

Serverless platforms allow developers to run code without managing traditional servers directly.

The cloud provider handles much of the underlying infrastructure.

Developers can focus on individual functions or services.

This can be useful for certain applications because resources can be allocated based on usage.

I find serverless computing interesting because it represents another level of abstraction in software development.

Instead of thinking about individual machines, developers can focus more directly on application logic.

Another concept I want to understand is event-driven architecture.

In an event-driven system, an action can trigger another process.

For example, when a user uploads a file, an event can trigger a function that processes the file.

This can allow different components of an application to operate independently.

I find this architecture useful for applications involving data processing and automation.

Another area I want to explore is microservices.

A large application can sometimes be divided into smaller services.

Each service can perform a particular function and communicate with other services through APIs.

This can make some systems easier to scale and maintain.

However, microservices also introduce additional complexity.

There are more services to deploy, monitor, secure, and communicate between.

I find this trade-off interesting.

Another area I want to understand is containerisation.

Containers allow applications and their dependencies to be packaged in a consistent environment.

This can make it easier to move applications between development, testing, and production environments.

Containers have become an important part of modern cloud development.

I want to learn more about how containerised applications are deployed and managed.

Another related technology is Kubernetes.

Kubernetes can help manage containerised applications across multiple machines.

It can handle tasks such as deployment, scaling, service discovery, and recovery.

I find Kubernetes interesting because it demonstrates how complex cloud systems can be automated.

At the same time, I understand that not every application requires such a complex architecture.

I want to learn how engineers decide when such tools are appropriate.

Another area I want to explore is infrastructure automation.

Manually configuring large numbers of cloud resources can be slow and error-prone.

Infrastructure as code allows infrastructure configurations to be described using files and managed systematically.

This can make deployments more repeatable.

It can also allow infrastructure changes to be reviewed and tracked.

I find this approach useful because it applies software engineering principles to infrastructure.

Another important area is continuous integration and continuous deployment.

Software applications often need to be updated regularly.

Automated pipelines can build, test, and deploy changes.

This reduces the amount of manual work required.

Cloud platforms can provide infrastructure for these workflows.

I want to understand how CI/CD systems help organisations deliver software reliably.

Another area I find interesting is monitoring.

After an application is deployed, developers need to know whether it is working correctly.

Monitoring systems can track metrics such as CPU usage, memory usage, request rates, response times, and errors.

Logs can provide additional information about what is happening inside the application.

This information can help developers identify problems.

I have become more interested in monitoring because running an application is different from simply developing it.

Another important concept is observability.

Observability involves using information from a system to understand its internal behaviour.

Metrics, logs, and traces can help identify where problems are occurring.

For example, if an application becomes slow, traces can help determine whether the problem is in the frontend, API, database, or another service.

I find observability important for large systems.

Another area I want to explore is cloud security.

Cloud applications can contain sensitive information.

Users may provide personal data.

Applications may store credentials, documents, financial information, or other important resources.

Cloud resources therefore need appropriate access controls.

Permissions should be limited to what is required.

Sensitive data should be protected.

I want to understand how secure cloud architectures are designed.

Another important concept is identity and access management.

Cloud platforms contain many different resources.

Users and services need permissions to access those resources.

Identity and access management systems allow organisations to control these permissions.

I find this important because a configuration mistake can potentially expose resources that should remain private.

This has strengthened my interest in cybersecurity.

Another area I want to understand is secrets management.

Cloud applications often require database credentials, API keys, certificates, and other sensitive information.

These should not simply be stored inside source code.

Secure systems need appropriate methods for storing and accessing secrets.

I want to learn how production applications handle these requirements.

Another important area is encryption.

Data stored in cloud systems may need to be protected.

Data transmitted between services may also need protection.

Encryption can help reduce the risk of sensitive information being exposed.

I want to understand how encryption is applied in cloud architectures.

Another area I find interesting is network security.

Cloud applications can contain different networks, services, and access points.

Not every component should be directly accessible from the public internet.

Network controls can help restrict communication.

I want to learn how cloud networks are designed to separate public and private components.

Another area I want to explore is virtual private networks and private connectivity.

Applications may need to communicate securely with internal systems or other cloud resources.

Private network connections can help keep certain traffic away from the public internet.

I find this useful because it shows how network architecture affects application security.

Another important topic is cloud cost management.

Cloud resources are often charged based on usage.

If an application uses more computing power, storage, or network traffic, costs can increase.

A system that is technically successful may still be poorly designed if it is unnecessarily expensive.

This made me realise that software architecture also has financial considerations.

I want to learn how engineers balance performance, reliability, and cost.

Another area I find interesting is autoscaling.

An application can automatically increase or decrease its resources based on demand.

This can help maintain performance during busy periods while reducing unnecessary resource usage during quieter periods.

Autoscaling is an example of automation being used to manage infrastructure.

I want to understand how autoscaling policies are designed.

Another important concept is high availability.

Critical applications may need to remain available even if some infrastructure components fail.

Cloud systems can use multiple availability zones or other redundancy mechanisms.

However, higher availability can increase complexity and cost.

I find this trade-off important to understand.

Another area I want to explore is disaster recovery.

A disaster recovery plan should consider how much data can potentially be lost and how quickly the service needs to be restored.

Another area I want to understand is backup management.

Important information should not depend on a single copy.

Backups can protect against accidental deletion, hardware failure, or other problems.

If an attacker can access both the primary data and backups, recovery may become more difficult.

I want to learn how secure backup systems are designed.
