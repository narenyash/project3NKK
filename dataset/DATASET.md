# Dataset — Phase 1 Finalization

Self-collected college admissions essay dataset for an AI-detector project: 300 essays
across three classes, normalized, quality-checked, topic-tagged, split, and paired with
a standalone fairness-check slice. This document is the single reference for what's in
`dataset/` and what its limitations are.

**Revision note:** this is the second pass over the dataset. The first pass flagged three
problems (length disparity, hybrid essays not matching their intended 60/40 blend, and
unreliable topic tags) as Known Limitations rather than silently patching them. This
revision actually fixes all three — see each item below for what changed and what, if
anything, remains an open limitation after the fix.

## Files

- `essays.jsonl` — all 300 records: `id, text, label, topic, topic_confidence, topic_candidates, genre, source, word_count, sentence_count, text_length_controlled, word_count_length_controlled, excluded, exclusion_reason`, plus `sentence_labels` and `human_source_id` on every `hybrid` record.
- `conversion_report.md` — Step 1–2 inventory/normalization issues (now just the 2 expected stub-source exclusions).
- `quality_report.md` — Step 4–5 quality and balance findings, including both raw and length-controlled word-count tables.
- `topic_coverage.csv` — topic × label counts (3-model consensus).
- `topic_low_confidence.md` — the 4 essays with genuine 3-way model disagreement on topic, for manual review.
- `splits.json` — locked 80/20 essay-level train/test split over the 296 usable records.
- `ellipse_fairness.jsonl` — standalone ELL fairness-check slice. Never merged into `essays.jsonl` or `splits.json`. Unaffected by this revision.
- `class AH_original_backup/` — the 100 original (pre-fix) hybrid essays, kept for comparison/audit.

## How each class was produced

- **human**: **not uniformly self-collected — two distinct sources**, corrected in this
  revision after being previously (inaccurately) described as entirely self-collected:
  - `Tab_1`–`Tab_28` (28 essays): real student essay submissions, self-collected.
  - `Tab_29`–`Tab_100` (72 essays): pulled from the public essay collection at
    [openessays.org](https://www.openessays.org/). The raw dump lives in root-level
    `OPEN_SOURCE_ESSAYS.txt`; `split_open_source_essays.py` split it into individual
    `Tab_29.txt`…`Tab_100.txt` files and merged them into `class H/` alongside the
    self-collected batch. (Verified via file timestamps: `Tab_1`–`Tab_28` are all
    timestamped from the original collection pass; `Tab_29` onward all carry the later
    timestamp from the `split_open_source_essays.py` run — `Tab_29.txt` specifically was
    overwritten by that script, since the split numbering restarted at 29.)
  - **Known gap**: `essays.jsonl` has no field distinguishing which half of `human` a
    given record came from — `source` reads the same generic value for both. A reader
    who needs this distinction today has to cross-reference the Tab number against the
    28/72 split documented here, not query it directly. Not fixed in this revision.
- **ai**: generated by a single AI model. Which model, what prompt, and what settings were used were not recorded at generation time — `source` honestly reads `"ai-generated (model/settings undocumented)"` (still an open limitation, see below). A separate, newer batch generated with full provenance logging exists in `Class A_v2/` — see the "AI source metadata is undocumented" limitation below.
- **hybrid**: for each valid human essay, `scripts/regenerate_hybrids.py` splits the essay into paragraphs (or sentences, if the essay lacks real paragraph breaks), deterministically selects ~40% of those units, sends only those to a local Ollama model (`mistral:latest`) for enhancement, and leaves the rest byte-for-byte untouched, then reassembles. This replaced the original method (whole-essay rewrite), which frequently ignored the 60/40 target — see fix #2.

## Sentence-level hybrid labeling

Every valid hybrid essay was sentence-diffed against its human original (`difflib.SequenceMatcher`
over spaCy sentence spans) to produce a `sentence_labels` array (`human` = verbatim,
`ai_edited` = new/altered). All 98 valid hybrids now show real, non-degenerate blending —
verbatim retention ranges 17.7%–81.9% (mean 41.5%, median 43.2%) instead of the previous
all-or-nothing pattern.

## Fixes applied this revision

### Fix 1 — Length disparity (was: critical risk)
**Non-destructive.** Every essay's original `text`/`word_count` is untouched (kept for
audit). A new `text_length_controlled` field truncates each essay at the last full
sentence at or before a **1000-word cap** (chosen as close to the human median of ~968
words); essays already under the cap are copied through unchanged.

| class | raw mean | length-controlled mean | length-controlled max |
|---|---|---|---|
| human | 998 | 826 | 999 |
| ai | 3,203 | 995 | 1,000 |
| hybrid | 1,597 | 948 | 1,000 |

**Use `text_length_controlled`, not `text`, for Phase 2 feature extraction/modeling** —
the three classes are now in a comparable range and length is no longer a free signal
for detecting `ai`. (Raw `text` still shows the old gap by design — that field is the
untouched original, not a bug.)

### Fix 2 — Hybrid generation missing its 60/40 target (was: 51/100 essays had 0% verbatim retention)
Replaced the whole-essay-rewrite method with a controlled paragraph/sentence-level blend
(see "How each class was produced" above) and regenerated all 98 valid hybrids (backup
of the originals kept in `class AH_original_backup/`). Result: every valid hybrid now
shows genuine partial retention (17.7%–81.9% human sentences, mean 41.5%) — no more
essays at or near 0% or 100%.

**Residual note:** the unit-selection target was 60% verbatim / 40% enhanced, but mean
sentence-level retention came out at 41.5% (i.e. ~58.5% of sentences flagged
`ai_edited`), somewhat more AI-heavy than the unit-level target. This is because
AI-enhanced paragraphs/sentences frequently expand into more sentences than the
original, which shifts the sentence-level ratio down even though the *unit* selection
ratio was exactly 40%. Every essay is well within a sane range (no more degenerate
0%/100% cases), but if an exact 60/40 sentence-level ratio matters for Phase 2, this is
a candidate for further tuning (e.g. selecting fewer units, or capping enhancement
length growth).

Two hybrids (`hy_021`, `hy_026`) could not be regenerated — their paired human "essay"
(`h_021`, `h_026`) is a 2-word stub with no real content to blend from. Both are now
excluded from the modeling-ready set (see Fix on exclusions below), not silently kept
as fabricated data.

### Fix 3 — Unreliable topic tagging (was: single model, false 100% confidence, 81% collapsed to one topic)
Replaced single-model tagging with **3-model consensus** (mistral, llama3, gemma4 — all
locally available). Each model tags independently; 2-or-3-way agreement is kept as
`topic` with `topic_confidence: "high"`; genuine 3-way disagreement is now the actual
low-confidence signal (`topic_candidates` records all three votes).

**What improved:** confidence is now honest. Previously 0/300 essays were flagged for
review despite an implausible 81% concentration in one topic. Now **4/300 essays show
real 3-way disagreement** (`h_009`, `h_014`, `h_019`, `h_045` — see
`topic_low_confidence.md`), which is a trustworthy signal you can act on.

**What did NOT improve:** the topic distribution is still heavily concentrated —
94% of essays (283/300) landed on `intellectual_curiosity` under majority vote, *more*
concentrated than the original single-model run (81%). Watching the three models tag
independently, each showed real topic diversity individually, but a 2-of-3 majority on
`intellectual_curiosity` was still common. This may partly reflect genuine content (these
are largely reflective, growth/curiosity-themed personal essays) rather than pure model
bias, but that hasn't been independently verified by manual reading. **Treat `topic` as
a rough, better-calibrated-but-still-skewed signal — a manual read-through of a sample
is recommended before trusting it for anything beyond loose stratification.**

## Fix — Stub-sourced records excluded from modeling
`h_021` and `h_026` are 2-word stubs (just a "Tab N" header, no real essay), and their
paired hybrids (`hy_021`, `hy_026`) had nothing genuine to blend from. All four are
marked `excluded: true` with `exclusion_reason` in `essays.jsonl` (kept for audit) and
are filtered out of `splits.json`. Usable class counts: `human` 98, `ai` 100, `hybrid` 98
(296 total).

## Remaining Known Limitations (not fixed this revision)

1. **AI source metadata is undocumented** for the original 100 `ai` essays specifically — one unspecified model, no recorded prompt/settings/temperature, and this is **not recoverable after the fact**: no logs or metadata exist for that batch, so this stays a permanent, disclosed limitation of that historical data rather than something silently patched or backfilled with a guessed source.
   **The process gap behind it is fixed going forward**, though: `scripts/generate_ai_essays.py` generates new `ai`-class essays via a documented model (`mistral:latest`, module constant `MODEL`) and a fixed, readable prompt template, writing every generation's exact model, prompt, options, and UTC timestamp to `dataset/ai_essay_generation_log.jsonl`. Verified working end-to-end (see that file for a real 3-essay demonstration batch, output in `Class A_v2/`). Any essay added to this corpus from now on has real, checkable provenance; the original 100 do not and never will. Folding `Class A_v2/` into the modeling set (and retraining) is a separate, deliberate step — see the note at the bottom of `generate_ai_essays.py`.
2. **Topic tagging is still skewed** (94% `intellectual_curiosity`) even after the consensus fix — see Fix 3 above for detail. Confidence is now trustworthy; the underlying distribution is not yet verified as accurate.
3. **Near-duplicates.** 59 essay pairs scored ≥0.85 TF-IDF cosine similarity (up slightly from 53, since regenerated hybrids retain more of their human original verbatim than the old fully-rewritten versions — expected, given human/hybrid pairs share real source text). Full pair list in `quality_report.md`; spot-check before training to rule out unwanted leakage between classes.
4. **Word-count outliers on raw `text`.** 229/300 essays fall outside the 250–1000 word range on the raw field — expected, since raw `ai` essays are still long by design (Fix 1 addresses this via `text_length_controlled`, not by altering raw `text`).
5. **Consent / privacy.** `Tab_1`–`Tab_28` are real, self-collected student essays — anonymization and consent status for wider sharing/publication has not been separately confirmed for these specifically, and should be before distributing this dataset beyond this project. `Tab_29`–`Tab_100` are pulled from a public essay collection (openessays.org) — treat their redistribution terms as governed by that site, not this project, and verify before distributing.
6. **`human` class has mixed provenance with no distinguishing field**, corrected in this revision — see "How each class was produced" above. Anyone filtering or analyzing `human` essays by source needs to cross-reference the Tab number range (1–28 vs. 29–100) manually; `essays.jsonl` doesn't carry this distinction as a queryable field.

## Train/test split (Step 7)

- Essay-level 80/20 split, stratified by `(label, topic)`, seed 42, over the **296 usable
  (non-excluded) records**, locked in `splits.json`.
- Final: `human` 78/20, `ai` 80/20, `hybrid` 78/20 (rounding + 2 exclusions per class where applicable).
- 2 `(label, topic)` combinations had only 1 essay and were kept entirely in `train`: `human/topic_that_captivates`, `human/accomplishment_gratitude`.
- Split is essay-level only — a hybrid's sentences (and its `sentence_labels`) always stay together on one side, so there's no sentence-level leakage across train/test.
- This split was regenerated as part of this revision (the underlying data changed materially — hybrids were rebuilt and 4 records excluded) — this re-lock is intentional, not silent reshuffling. `splits.json` should now be treated as the stable lock going forward.

## ELLIPSE fairness slice

`ellipse_fairness.jsonl` — 3,911 essays from the public [ELLIPSE corpus](https://github.com/scrosseye/ELLIPSE-Corpus) (English Language Learner writing samples, no auth required to download), normalized to `{id, text, label: "human", is_ell: true, source}`. Not part of `essays.jsonl`/`splits.json`, never used for training, reserved for a Phase 4 false-positive-rate check. Unaffected by this revision.

## Pipeline (for reproducibility)

Run in order from `scripts/`:

```
python regenerate_hybrids.py  # Rebuilds class AH/ with a controlled paragraph/sentence blend (backs up originals)
python build_dataset.py       # Steps 1-2: inventory, normalize, hybrid sentence diff, mark exclusions
python length_normalize.py    # Adds text_length_controlled / word_count_length_controlled (1000-word cap)
python sentence_segment.py    # Step 6: sentence counts on the raw text field
python topic_tagger.py        # Step 3: 3-model consensus topic inference (slow - ~900 LLM calls)
python quality_checks.py      # Steps 4-5: dedup/outlier/balance checks, whitespace auto-fix
python make_split.py          # Step 7: locked train/test split, excludes stub-sourced records
python fetch_ellipse.py       # Step 8: download + normalize the ELLIPSE fairness slice (only needed once)
```
